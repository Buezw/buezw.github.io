Avellaneda-Stoikov 做市策略：模拟报告

从零实现 A-S 闭式做市模型的 Python 蒙特卡洛模拟，附毒性流冲击测试与 OFI 信号实验，如实报告结果。

库存感知做市模型的从零实现与压力测试 | Market-Maker-Strategy/python

Avellaneda, M. & Stoikov, S. (2008). “High-frequency trading in a limit order book.” Quantitative Finance, 8(3), 217–224. DOI: 10.1080/14697680701381228

一、我做了什么
#

在原有的 C 语言限价订单簿撮合引擎（engine/，仅 3 档离散价位、无浮点运算，为裸机环境设计）之上，另起了一个独立的 Python 子项目（python/），从零实现 Avellaneda & Stoikov (2008) 论文里真正的闭式做市模型，而不是把这套连续价格、连续做市强度的数学，硬塞进一个只有 3 个价位槽的离散撮合引擎里。

具体做了四件事，对应最初提的四个要求：

  • 模拟 mid-price：中间价按论文原设定，走算术布朗运动 $dS = \sigma\, dW$。
  • 按库存调整 reservation price：库存为正（多头）会把报价中枢往下拉（更想卖出），库存为负（空头）反之，具体公式见第二节。
  • 计算最优 bid/ask：闭式最优价差公式，两档对称挂在 reservation price 两侧。
  • 跟踪库存与 P&L：逐 tick 记录库存、现金、按当前中间价 mark 的浮动盈亏，蒙特卡洛批量跑几千条路径统计终局分布。

然后按要求做了两个进阶模块：一个 order flow imbalance 信号，一个 adverse selection / toxic flow 冲击测试。这两块没有为了效果好看去调参——下面第四、五节会把真实测出来的数字和为什么会是这个结果都如实写出来，包括一开始设计错了、后来怎么改对的过程。

二、模型：论文原始公式
#

论文用指数效用的做市商，中间价 $S_t$ 服从算术布朗运动，订单簿里离中间价距离 $\delta$ 的挂单以 Poisson 强度成交：

$$ \lambda(\delta) = A \cdot e^{-k\delta} $$

求解做市商的 HJB 方程，得到闭式的 reservation price（在当前库存 $q$ 下，做市商对多持一单位和少持一单位无差别的价格）：

$$ r(s,q,t) = s - q\gamma\sigma^2(T-t) $$

对应的最优总价差，两档对称挂在 $r$ 两侧：

$$ \delta_{\text{total}} = \gamma\sigma^2(T-t) + \frac{2}{\gamma}\ln\!\left(1+\frac{\gamma}{k}\right) $$$$ \text{bid} = r - \frac{\delta_{\text{total}}}{2} \qquad \text{ask} = r + \frac{\delta_{\text{total}}}{2} $$

$\gamma$ 是做市商的风险厌恶系数，$\sigma$ 是波动率，$k$ 是订单簿厚度（越大表示挂单要越贴近中间价才能成交），$A$ 是零距离处的基础成交强度。全部符号含义、公式出处见 avellaneda_stoikov/model.py 的 docstring。

实现上用 numpy 把蒙特卡洛的每一条路径都当成数组里的一条车道，同一个时间循环里所有路径并行推进——因为路径之间彼此独立，唯一真正的递归关系是沿着时间展开的（库存、现金都依赖到当前为止的整条成交历史），不需要对每条路径单独写 Python 循环。

三、核心结果：AS 策略 vs. 对称策略（不做库存调整）
#

论文自己的对照组（Sec. 4）：把 reservation price 里的 $q$ 项去掉，其余（价差公式、成交模型）完全一样，这样能干净地隔离出库存偏斜这一项到底带来了什么。参数用论文原始算例：$s_0=100$, $T=1$, $\sigma=2$, $\gamma=0.1$, $k=1.5$, $A=140$, $dt=0.005$（200 步/条路径），5000 条路径。

策略 PnL 均值 PnL 标准差 库存标准差 平均最大|库存|
symmetric（对称） 61.05 8.15 8.12 9.64
as（库存偏斜） 57.29 5.74 3.00 4.09

这正是论文的核心结论：AS 策略放弃了一点点均值 PnL（约 6%），换来终局 PnL 分布标准差降低 30%，库存风险只有对称策略的三分之一左右——用更少的尾部风险换取更稳的收益，而不是单纯赚得更多。

四、进阶一：Adverse Selection / Toxic Flow 冲击测试
#

怎么建模毒性流
#

论文本身假设订单流是无信息的 Poisson 过程——它自己的模型里，永远没有对手方比做市商更了解下一步价格会怎么走。真实的毒性流打破了这个假设：一部分对手方确实知道点什么，专挑做市商即将被打穿的那一侧下单。

实现方式：每个 tick 以概率 jump_prob 触发一次价格跳跃（大小 jump_size），跳跃幅度特意设得比半个价差还大——因为普通一个 tick 的扩散幅度（$\sigma\sqrt{dt} \approx 0.14$）远小于半价差（$\approx 0.85$），如果用下一 tick 会往哪走这么短的预见期去建模知情交易，冲击测试根本测不出任何效果（这是实际跑出来才发现的，见下方踩过的坑）。toxicity $\in [0,1]$ 控制这次跳跃里有多少比例的流量是知情的：跳跃发生时，即将被打穿的一侧（价格要涨就是卖价，要跌就是买价）成交概率会被推向 1。

两个诚实的发现（不是一开始预想的）
#

  • 毒性确实单调拖累 PnL，但在这组参数下幅度不算大。 第一版冲击测试用下一 tick 作知情预见期，测出来 toxicity 几乎没有可观测的影响——半价差每次都稳赢过普通扩散的幅度。直到把知情交易明确建模成提前知道一次和价差同量级的跳跃，效果才显现。这本身就是一个值得记录的发现：对称/AS 报价策略要感觉到逆向选择，冲击幅度得和它能拿到的补偿（价差）在同一个量级上，不然根本不痛不痒。
  • as_defensive（用 signals.ToxicityProxy 这个简化版 VPIN 信号反应式加宽价差）基本是打平的，没有明显帮助。 它会让全程成交量少掉约 20%（价差变宽，连正常无信息的订单流也被挡在外面），只有在毒性最高的那一档才勉强反超一点点。原因是结构性的，不是没调好参：ToxicityProxy 完全基于过去的成交历史构建，而这个测试里的跳跃是瞬时、逐 tick 独立的——对一个只能往回看的信号来说，没有任何在跳跃发生前能抓到的痕迹。VPIN 这类毒性指标在文献里本来就是设计来抓持续性的单边知情流（比如 Flash Crash 前的那种机构订单流），不是用来抓孤立冲击的。第一版图省事直接把 vpin_kappa 设成 2.0，结果更糟——滚动窗口里成交笔数太少（约 18 笔），单靠二项分布的抽样噪声就经常显得失衡，几乎一直在自己吓自己地加宽价差，哪怕注入毒性为零，PnL 也直接腰斩。0.3 是调得更保守的一版，不是解决了这个问题。

五、进阶二：Order Flow Imbalance 信号
#

思路来自 Cont, Kukanov & Stoikov (2014)：净订单流失衡能预测短期价格走向。这里用这个模拟器自己产生的净签约成交流量（我方买入 − 我方卖出，在滚动窗口内求和）作为论文原版全订单簿队列变化的简化替代，用一个 ofi_theta 参数把它线性叠加进 reservation price。

图 4：均值 P&L 随 OFI 倾斜强度变化（toxicity=0.3，4000 条路径/格）——小幅正向倾斜有边际收益，过了某个量级后迅速崩坏。（原文为图表，见 PDF 版）

在 ofi_theta ≈ 0.5–1.0（顺着最近的净成交流量小幅拉动 reservation price）能看到一个稳定、可跨随机种子复现的小幅收益（约 +0.5∼0.6，换来更高的方差）。但过了 theta ≈ 2 之后同一个（未做截断的）线性倾斜项开始起反作用，到 theta=10 直接崩溃。原因两边一致：ofi_theta 直接乘在一个没有裁剪的滚动均值上，一段本身只是噪声、并非真正知情的成交流，也能把 reservation price 甩出去好几倍价差。这条曲线的形状比某个具体的最优值更值得记住——顺着已实现流量小幅调整确实有真实的边际收益，但这个收益很脆弱；这正是为什么真实生产系统里，基于信号的调整都会做裁剪/衰减而不是直接线性叠加，报告里特意把这个失败模式也保留下来展示，而不是只放调好的那一个值。

六、诚实说明：已知局限
#

  • 中间价过程没有 regime 结构——没有真实市场的波动率聚集、成交量相关的跳跃、动量；除冲击测试专门加的跳跃外，其余部分严格按论文假设走纯 $\sigma$ 恒定的算术布朗运动。
  • 成交是单位大小、逐边独立的 Poisson 事件——没有队列位置、没有部分成交、没有深度，这是论文自己的简化，不是这里额外加的。
  • 两个信号模块的效果如实报告，没有挑好看的数字：OFI 有真实但脆弱、容易被自己的幅度反噬的边际收益；毒性防御在这个模拟器注入的（瞬时型）毒性下基本打平，需要真正持续性的毒性 regime 才有公平发挥的机会。
  • 跑在 Python 3.6.8、没有 pandas/pytest 的环境里——测试套件是和 C 项目 tests/test_market_maker.c 一样的纯 assert + print PASS/FAIL 风格，没有框架依赖。
